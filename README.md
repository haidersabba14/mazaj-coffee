# ☕ مزاج — قهوتك على مزاجك

موقع عربي RTL مبني على Cloudflare Workers + Static Assets + D1، بواجهة دون إطار ثقيل، وسلّة، وطلبات محفوظة، وتتبع برمز سري، ولوحة إدارة، وTurnstile، وإشعارات Resend مع إعادة المحاولة.

## قواعد المقهى الحالية

- نفتح يوميًا **٣ عصرًا بتوقيت البحرين**. يمنع الخادم تأكيد الطلب قبل الفتح. الاستقبال حتى منتصف الليل، مع إغلاق يدوي من الإدارة. لم يحدد المالك ساعة إغلاق أخرى.
- كل مشروب سعره **٢٫٠٠٠ دينار بحريني** (٢٠٠٠ فلس).
- **اليوم فقط، ١٣ نوفمبر ٢٠٢٦ بتوقيت البحرين: جميع المشروبات مجانية**. ينتهي العرض عند `2026-11-13T21:00:00Z`، بداية يوم ١٤ نوفمبر في البحرين. لا يتكرر العرض تلقائيًا. بعده الدفع عند الاستلام؛ لا توجد بوابة دفع إلكترونية.
- الاستلام من المقهى فقط، لا رسوم توصيل أو رسوم خفية.
- تُحسب الأسعار والخصومات في الخادم، مع رفض الإجمالي القديم عند تغيّر العرض قبل التأكيد.

## ما تم وما لم يتم التحقق منه

تم بناء الحزمة والتحقق من إعداد النشر دون رفعها، وتشغيل اختبارات تكامل حقيقية على محرك Workers المحلي وقاعدة D1 محلية. اختبارات Turnstile وResend المحلية تستعمل استجابات محاكاة، وليست إثباتًا لإرسال بريد حقيقي. تم إنشاء Turnstile حقيقي للعنوان المنشور وحفظ سره في Cloudflare، وضبط سر الإدارة وrate salt والتحقق من تسجيل الدخول الفعلي. لا يزال Resend غير مهيأ، ولم يُختبر بريد حقيقي. لا تعرض الواجهة نجاحًا قبل نجاح حفظ الطلب.

أُنشئت قاعدة D1 سحابية فعلية باسم `mazaj-coffee` بمعرّف `170439f5-0c0c-4169-9d54-a2d4dbdf8740` في حساب المالك `ba74814ba7d8c1f67239ea195089ff2c` عبر اتصال Cloudflare الخارجي، وطُبّق الترحيل وسُجل، وتم التحقق من المشروبات السبعة وموعد ١٥:٠٠ وتاريخ العرض. نُشر Worker بنجاح على https://mazaj-coffee.haider-sabba.workers.dev وتم التحقق من الصفحة والقائمة والصور ورفض الوصول غير المصرح للإدارة (401). لا توجد مفاتيح CLI أو Resend أو Turnstile في بيئة الأوامر الحالية. أنشأ المالك المستودع https://github.com/haidersabba14/mazaj-coffee لرفع المشروعين وتشغيل Actions. أدوات التحكم بالمتصفح غير متاحة في هذه الجلسة؛ التحقق البصري التفاعلي على الأجهزة الحقيقية لا يزال مطلوبًا.

## التشغيل المحلي

يتطلب Node.js 24 وnpm. المشروع يستخدم Cloudflare CLI `cf` وإعداد `cloudflare.config.ts`، مع إصدارات beta مثبتة في package-lock لأن إعداد cf البرمجي لا يزال في beta.

```sh
npm ci
npm test
npm run build
npx cf deploy --dry-run
```

للواجهة مع API محلي وقاعدة تطوير، أنشئ ملف `.dev.vars` **محليًا فقط** بالأسماء التالية:

```dotenv
TURNSTILE_SECRET=your-secret
ADMIN_PASSWORD_HASH=salt:pbkdf2-hex
RATE_SALT=random-32-byte-secret
RESEND_API_KEY=your-key
```

مفتاح الموقع العام ومرسل البريد ومعرّف القاعدة تُقرأ من متغيرات بيئة عملية البناء: `TURNSTILE_SITE_KEY`, `EMAIL_FROM`, `D1_DATABASE_ID`. إعدادات وأسرار `cf` المحلية قد تختلف عن إعدادات الاختبارات؛ لا تضف تجاوزًا أمنيًا لبيئة الإنتاج. استخدم مفاتيح Turnstile التجريبية الرسمية للاختبار المعزول، مع إبقاء فحص hostname وaction مضبوطًا. الطلب في بيئة الاختبار المحلي لا يرسل بريدًا فعليًا.

لتطبيق الترحيل المحلي دون حساب Cloudflare:

```sh
export D1_DATABASE_ID=10000000-0000-4000-8000-000000000001
npx cf d1 migrations apply "$D1_DATABASE_ID" --local
npm run dev
```

واجهة الإدارة `/admin.html`. الدخول محمي بالـAPI؛ ملف HTML وحده لا يحتوي بيانات عميل. الاختبارات تستعمل Miniflare 4 بتاريخ توافق `2026-08-06` (أقصى تاريخ يدعمه محرك الاختبار المثبت)، بينما إعداد الإنتاج بتاريخ `2026-11-13`. بناء الإنتاج يتحقق أيضًا عبر نسخة runtime الخاصة بـcf. يلزم اختبار نشر فعلي قبل الفتح للجمهور.

## النشر على Cloudflare — الخطة المجانية

1. أنشئ حساب Cloudflare على Workers Free، وفعّل نطاق workers.dev. لا تفعّل خطة مدفوعة. رابط الإنتاج الحالي: https://mazaj-coffee.haider-sabba.workers.dev . للتحديث من جهازك سجّل الدخول:

   ```sh
   npx cf auth login
   ```

2. القاعدة الحالية جاهزة ومربوطة افتراضيًا في الإعداد؛ لا تنشئ نسخة ثانية. استخدم `D1_DATABASE_ID=170439f5-0c0c-4169-9d54-a2d4dbdf8740`. فقط عند نقل المشروع لحساب آخر، أنشئ قاعدة جديدة من اللوحة أو بالأمر:

   ```sh
   npx cf d1 create --name mazaj-coffee
   ```

   خذ UUID الناتج وضعه في `D1_DATABASE_ID` في بيئة الأوامر وGitHub Actions Variables. `CLOUDFLARE_ACCOUNT_ID` هو معرّف حسابك. لا تستخدم UUID المثال المحلي في الإنتاج.

3. الترحيل الأول مطبق على القاعدة الحالية، وسجل `d1_migrations` موجود. الأمر التالي يتحقق من الترحيلات غير المطبقة ويطبقها عند الحاجة:

   ```sh
   npx cf d1 migrations apply "$D1_DATABASE_ID"
   ```

4. أنشئ Turnstile Managed Widget مجانيًا في لوحة Cloudflare. اسمح باسم مضيف workers.dev الفعلي. ضع Site Key العام في `TURNSTILE_SITE_KEY` قبل البناء، وSecret Key في Workers Secrets. الخادم يتحقق من النجاح واسم المضيف و`action=checkout`. لا تستخدم مفاتيح الاختبار في الموقع العام.

5. اختر كلمة مرور إدارة طويلة وفريدة (١٤ حرفًا فأكثر). أنشئ البصمة دون كتابة كلمة المرور في سجل الأوامر، في shell محلي موثوق:

   ```sh
   read -r -s -p 'Admin password: ' MAZAJ_PASSWORD
   printf '%s' "$MAZAJ_PASSWORD" | npm run --silent password:hash
   unset MAZAJ_PASSWORD
   ```

   احفظ الناتج فقط باسم `ADMIN_PASSWORD_HASH` في Workers Secrets؛ لا تضع كلمة المرور أو البصمة في Git. تستخدم البصمة PBKDF2-SHA256 بـ١٠٠ ألف دورة، والجلسة عشوائية ٢٥٦ بت وملف ارتباط HttpOnly/Secure/SameSite=Strict لمدة ٨ ساعات، مع تحديد محاولات الدخول. ولّد `RATE_SALT` عشوائيًا بأداة محلية واحفظه سرًا أيضًا.

6. جهّز البريد كما في القسم التالي. ابنِ وانشر أولًا (سيظل الطلب مغلقًا أمنيًا ما دام Turnstile غير مهيأ):

   ```sh
   npm run deploy
   ```

   أضف الأسرار من صفحة Worker → Settings → Variables and Secrets: `TURNSTILE_SECRET`, `ADMIN_PASSWORD_HASH`, `RATE_SALT`, `RESEND_API_KEY`. اضبط `EMAIL_FROM` في بيئة البناء إلى عنوان موثّق، ثم أعد البناء والنشر عند تغييره. لا تضع الأسرار في ملف الإعداد. يمكن إدخال الأسرار مع النشر باستخدام `cf deploy --secrets-file` من ملف محلي مستبعد من Git، ثم حذفه بأمان. لا تطبع الملف في سجل CI.

7. تأكد من وجود Cron `*/10 * * * *` في إعدادات Worker. يتولى إعادة محاولات البريد حتى ٥ مرات وتنظيف بيانات الطلبات الأقدم من ٣٠ يومًا، والجلسات وحدود المحاولات المنتهية.

8. افتح لوحة الإدارة واختبر الدخول، وإيقاف الاستقبال، والطلب بعد وقت الفتح، والتتبع، وتغيير الحالة، وإخفاء منتج. اختبر رابطين على هاتف وكمبيوتر قبل الإطلاق. لا تدّع وصول البريد إلا بعد فحص البريد الوارد فعليًا.

## إعداد Resend واختبار البريد

- أنشئ حساب Resend Free ومفتاح إرسال محدودًا إن أمكن. أضف المفتاح في Workers Secrets باسم `RESEND_API_KEY`.
- للإرسال الطبيعي أضف نطاقًا تملكه في Resend وانسخ سجلات DNS المطلوبة لـSPF/DKIM، وانتظر حالة Verified. لا يمكن توثيق `workers.dev` أو `icloud.com` لأنك لا تملك DNS لهما.
- اضبط `EMAIL_FROM` مثل `مزاج <orders@your-domain.example>` إلى عنوان على نطاقك الموثّق. **المستلم ثابت**: `haider.sabba@icloud.com`.
- إذا لم تملك نطاقًا، يتيح وضع تجربة Resend الإرسال من `onboarding@resend.dev` إلى البريد الخاص بحساب Resend فقط. إذا كان حساب Resend مسجّلًا بنفس بريد iCloud المستهدف، تحقّق من القيد من لوحة المزود وجرّب الإرسال؛ لا يُفترض أنه يسمح بالإرسال لأي عنوان. إن لم يتوافق ذلك، تبقى لوحة الإدارة بديلًا مجانيًا لاستقبال الطلبات إلى حين توفير نطاق موثّق. لا يوجد إرسال إنتاجي مضمون إلى عنوان اعتباطي دون إعداد المزود.
- نفّذ طلبًا حقيقيًا بعد تهيئة Turnstile، وسجّل رقم الطلب. في الإدارة: الحالة `تم قبول الإرسال` تعني HTTP ناجحًا من Resend؛ تحقق من Inbox وJunk ومن لوحة Resend. ليس لدينا webhook لتأكيد التسليم أو الارتداد.
- يتضمن البريد رقم الطلب والعميل والهاتف، ووقت البحرين، والكميات والملاحظات وطريقة الاستلام والإجمالي الفعلي وحالة جديد، بتصميم HTML ذهبي وأسود مع ترميز مدخلات العميل.
- فشل البريد لا يلغي الطلب المحفوظ. يسجّل `failed` ويمكن إعادة المحاولة يدويًا أو تلقائيًا. مفتاح idempotency خاص بالطلب يمنع تكرار إرسال المزود ضمن نافذته (عادة ٢٤ ساعة)؛ إعادة محاولة يدوية بعد النافذة قد ترسل نسخة إضافية. يحتفظ صندوق البريد بنسخته مستقلًا عن حذف D1.

## GitHub والتحديث

المشروع يحتوي CI للاختبار والبناء على push/PR، ونشرًا يدويًا من Actions لتفادي نشر غير مهيأ. بعد إنشاء مستودع فارغ وإعطاء التكامل صلاحية الكتابة:

```sh
git remote add origin https://github.com/YOUR_ACCOUNT/mazaj-coffee.git
git push -u origin main
```

أضف GitHub Actions Secret: `CLOUDFLARE_API_TOKEN` بأقل صلاحيات Workers Scripts Edit وD1 Edit للحساب المقصود (قد تحتاج Account Settings Read لإدارة النطاق الفرعي أول مرة)، وVariables: `CLOUDFLARE_ACCOUNT_ID`, `D1_DATABASE_ID`, `TURNSTILE_SITE_KEY`, `EMAIL_FROM`. راجع الـscopes في Cloudflare عند إصدار الرمز. أسرار التشغيل الأربعة تبقى في Cloudflare، وليست هناك حاجة لوضعها في GitHub. شغّل Workflow «Deploy to Cloudflare». عند تعديل Site Key أو EMAIL_FROM أعد البناء لأنهما متغيرا إعداد.

## حدود الخطط المجانية

تمت مراجعة الوثائق في ١٣ نوفمبر ٢٠٢٦؛ راجعها قبل الإطلاق لأنها تتغير:

| الخدمة | حدود الخطة المجانية |
|---|---|
| Workers | ١٠٠ ألف طلب ديناميكي/يوم، و١٠ms CPU لكل استدعاء. انتظار الشبكة لا يحسب CPU. قد يحتاج تسجيل الدخول/الإحصاءات إلى قياس فعلي ضمن الحد؛ لا نرقّي تلقائيًا. |
| Static Assets | طلبات الأصول الساكنة مجانية، مع حدود لحجم/عدد الملفات. |
| D1 | ٥ ملايين صف مقروء/يوم، ١٠٠ ألف صف مكتوب/يوم، ٥GB إجمالي تخزين، حتى ١٠ قواعد مجانية. كل استعلام إداري أو retry قد يستهلك حصصًا. |
| Turnstile | خطة مجانية مناسبة للنموذج، مع الالتزام بشروط المزود. |
| Resend Free | ٣٠٠٠ رسالة/شهر وبحد ١٠٠ رسالة/يوم وفق الخطة الحالية؛ بريد واحد لكل طلب. عند استنفاد الحصة تبقى الطلبات في الإدارة وتفشل إشعارات البريد حتى السماح بالإرسال. |
| GitHub | مستودع خاص وActions ضمن الحصة المجانية للحساب؛ يُمكن النشر محليًا لتوفير دقائق Actions. |

لا سيرفر خاص ولا خدمة مدفوعة مفعّلة. شراء نطاق مخصص للبريد اختياري وقد يكلف مالًا؛ البديل المجاني المقيّد هو وضع تجربة Resend إلى بريد الحساب أو الاكتفاء بلوحة الإدارة. سجلات Cloudflare والمراقبة تُستهلك ضمن حصص الحساب؛ راقبها دون تفعيل خطة مدفوعة.

المراجع: [Workers](https://developers.cloudflare.com/workers/platform/limits/) · [D1](https://developers.cloudflare.com/d1/platform/pricing/) · [Resend](https://resend.com/pricing) · [Turnstile](https://developers.cloudflare.com/turnstile/) · [cf](https://developers.cloudflare.com/cf/)

## الأمان والبيانات

- استعلامات D1 ذات معاملات، تحقق من الكميات (٢٠ للنوع، ٣٠ للإجمالي) والأسماء والهاتف والملاحظات، حد ١٦KB للطلبات، ورفض JSON غير السليم.
- أقصى ٥ محاولات طلب/١٠ دقائق لكل عنوان شبكة، و٥ محاولات دخول/١٥ دقيقة، و٢٠ محاولة تتبع/١٠ دقائق؛ المعرّفات الشبكية تُجزّأ مع salt ويجري حذفها دوريًا. قد يتشارك عملاء الشبكة الواحدة الحصة.
- رقم الطلب UUID ورمز متابعة عشوائي ٢٥٦ بت؛ يُحفظ hash الرمز فقط. التتبع لا يعرض الاسم أو الهاتف. لا تُضع الرموز في روابط URL. تُحفظ بيانات المتابعة في جلسة المتصفح مع إمكانية تنزيلها محليًا.
- منع التكرار عبر UUID ومقارنة بصمة بيانات الطلب والرمز، ومفتاح فريد في D1.
- حماية APIs الإدارية بالجلسة، والتحقق من Origin لعمليات الكتابة لمنع CSRF، وسياسة CSP وترويسات أمان، ولا سجلات لأجسام الطلب أو البيانات الشخصية. فعّل HTTPS الافتراضي على workers.dev.
- صور المنتجات قابلة للتعديل بروابط HTTPS؛ لا يوجد رفع ملفات إلى تخزين خارجي مدفوع. يمكن أيضًا إضافة ملفات محلية تحت public/images عبر GitHub. صورة احتياطية محلية عند فشل التحميل.
- الإحصاءات اليومية بتوقيت البحرين، الأسبوعية آخر ٧ أيام، واستبعاد الملغي من ترتيب المشروبات الأكثر طلبًا. البيانات محفوظة ٣٠ يومًا؛ لا تمثل الإحصاءات سجلًا تاريخيًا دائمًا.
- سجل السلة في localStorage، بيانات آخر تتبع في sessionStorage؛ البيانات الشخصية لا تحفظ محليًا. PWA يخزّن الصور محليًا فقط، ولا يخزّن APIs أو بيانات الإدارة أو صفحة النجاح. تأكيد الطلب يتطلب اتصالًا.

## انتظار قبول الطلب وتطبيق iPhone

الحالة الأولى في واجهة العميل والإدارة **بانتظار القبول** (`new` في قاعدة البيانات). تظهر شاشة «تم إرسال طلبك، يرجى انتظار القبول» بعد الحفظ فقط. في الإدارة زر **قبول الطلب** ينقله إلى قيد التجهيز، وزر **رفض الطلب** يلغيه. يتابع العميل النتيجة برقم الطلب والرمز، وتتحدث حالة شاشة الإرسال تلقائيًا كل ٤٥ ثانية ما دامت مفتوحة.

يتضمن `ios/` مشروع تطبيق إدارة iPhone/iPad، وWorkflow بناء IPA موقّعة عبر GitHub. راجع [تعليمات iOS](ios/README.md). بُني التطبيق فعليًا عبر GitHub Actions بنجاح، وأنتج IPA غير موقعة في [هذا التشغيل](https://github.com/haidersabba14/mazaj-coffee/actions/runs/43403640495). لم تُوقّع النسخة ولم تُختبر على جهاز iPhone فعلي. الإشعارات داخله فقط أثناء فتحه؛ APNs خلفية غير مفعّلة. التوزيع على أجهزة مسجّلة يتطلب شهادات Apple وعضوية مناسبة، وقد تكون لها تكلفة؛ لم تُفعّل أي خدمة مدفوعة. يمكنك تثبيت الموقع كتطبيق PWA مجانًا دون ملف IPA.

## التصميم الجديد

أُعيد بناء الواجهة من الصفر بتصميم داكن، وصورة دائرية كبيرة، وثلاثة أعمدة للمشروبات، وقسم مستقل للكوفي السري. يوجد وضع فاتح اختياري. اختبارات DOM تفحص الفلترة والكميات وحفظ السلة وعدم ظهور النجاح عند فشل الحفظ وحالة انتظار القبول؛ ليست بديلًا عن اختبار بصري على الأجهزة.


## الإدارة في التطبيق دون رمز تفعيل

أزيلت لوحة إدارة الويب ورابطها من موقع العملاء. المسارات `/admin`, `/admin.html`, `/admin.js` تعيد 404. تطبيق iOS واجهة SwiftUI أصلية للطلبات والمشروبات والإعدادات، ولا يعرض موقع العملاء.

حُذف رمز تفعيل الجهاز وشروط `ADMIN_APP_TOKEN` و`X-Mazaj-App-Key`. الدخول بكلمة مرور الإدارة فقط، مع جلسة HttpOnly/Secure وتحديد محاولات الدخول؛ الـAPI يرفض قراءة الطلبات دون جلسة صحيحة. لا تعتمد الحماية على نوع الجهاز: من يملك كلمة المرور يستطيع استعمال API من أي عميل، رغم عدم وجود لوحة إدارة على موقع العملاء.

نزّل أحدث IPA من GitHub Actions ووقّعها قبل التثبيت. النسخ السابقة قد تعرض خانة تفعيل قديمة؛ لن تختفي إلا بتحديث التطبيق. كلمة المرور غير مضمّنة في المصدر أو ملف التطبيق. إشعارات الخلفية APNs غير مفعلة.

## تحديث الموقع وبطاقة الولاء

الرابط الجديد https://mazaj-cafe-995.pages.dev بدون اسم صاحب الحساب. تعمل Pages Functions بنفس Worker وبنفس D1؛ بقي Worker السابق للمهام المجدولة وتنظيف البيانات. لا نغيّر نطاق حساب Workers العام لأنه يخدم مواقع أخرى.

كل المشروبات مجانية وفق آخر طلب، بما فيها اللاتيه المثلج والماء البارد والحار. حد الطلب مشروب واحد، أو مشروبان عند استبدال مكافأة ولاء. التوصيل مجاني ويطلب إحداثيات موقع البيت؛ موقع العميل لا يظهر في واجهة التتبع العامة. الاستقبال يوميًا بعد ٣ عصرًا بتوقيت البحرين.

صفحة `/card.html` تصدر بطاقة باسم الزبون ورقم تلقائي وQR. رمز QR يحتوي رقم البطاقة فقط؛ لا يمنح صلاحية الختم أو الاستبدال. الزبون يحتفظ برمز ملكية خاص على جهازه، ويمكنه حفظ نسخة احتياطية. يقرأ المسؤول البطاقة من التطبيق ويضيف ختمًا واحدًا لكل مسح؛ خمس ختمات تمنح مشروبين. الأحداث ذات مفاتيح فريدة، والاستبدال ومعالجة رصيد المكافأة داخل معاملة D1 لمنع الصرف المكرر.

النسخة توفر بطاقة QR حقيقية، وليست ملف Apple Wallet موقّعًا. توجد طريقة يدوية اختيارية عبر Pass2U لاستيراد QR وإنشاء نسخة Wallet بقالب مجاني؛ القوالب المدفوعة اختيارية. لم نختبر الاستيراد على iPhone فعلي، ولا تتحدث رسمة الختمات داخل النسخة اليدوية تلقائيًا. الإضافة المباشرة من موقعنا تتطلب شهادة جهة إصدار.

فُحص إصلاح Turnstile: كانت تسمية عنصر HTML `turnstile` تمنع تحميل المكتبة؛ تغير الاسم إلى `turnstile-widget`، ويُحمّل التحقق عند فتح السلة. لا يوجد تجاوز للتحقق في الإنتاج. اختبارات الحفظ المحلية تحاكي مزوّد Turnstile؛ اختبار إصدار طلب حقيقي يحتاج إكمال التحقق في المتصفح.

البريد إلى صاحب المقهى غير مهيأ حتى إضافة Resend ومُرسِل موثّق؛ فشل البريد لا يلغي الطلب المحفوظ. ميزات APNs خلفية وApple Wallet المباشر وحسابات الموظفين و2FA والعضويات المتقدمة ليست مفعلة. قائمة ١١٠ ميزة ليست مكتملة؛ لا تُعرض عناصر وهمية تدعي تشغيلها. المنفذ يشمل: الطلب والتخصيص والحفظ والتتبع والقبول والرفض والوقت التقديري، الخريطة، بطاقات الولاء، البحث والمفضلة وإعادة الطلب والمفاجأة واللغتين والمظهرين وPWA وحماية الإدارة.
